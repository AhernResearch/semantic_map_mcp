# 检索拼图首轮试验

实现已完成。本轮没有证明整轮任务提速，拼图保留在独立试验服务供进一步验证。

## 实现与工具验收

- 本地 Agent 与 harness MCP 通过 preview.call_for_model 共用拼图；每次 search_candidates 返回当前页最多5个候选的1张拼图，保留ID、原图面板坐标、第二视角入口和缺图错误。
- 原始 search_candidates API及召回算法不变；原始JSON和宿主派生图片审计分开保存。
- Agent 可引用实际有图的候选拼图直接 finish；缺图对象不能借拼图通过证据校验。
- 地图16项 unittest、harness地图4项测试通过。harness全量250通过，仍有2项已在原始基线复现的 reset_context 工具说明失败；Ruff/mypy与前端构建通过。
- MCP试验地址 `http://172.22.162.253:8880/mcp`，沿用8879的令牌；完整连接配置：`/home/agiuser/lx_workspace/runtime/map-mcp/map-query-mcp-preview-f910779724ba/client-config.json`。原8879进程不变。
- 实际HTTP工具调用：`a white cabinet` 检索一次返回5候选、1张1800×800 PNG，约0.62秒，响应约779KB。证据和源码指纹位于上述运行目录。

## 真实模型对照

相同 M-floor 快照、ViT-H-14 编码器、claude-sonnet-5-5 网关，按顺序分别执行旧流程和拼图流程，各任务各1次。最大8轮，无自动重试或替代模型；两版仅调整拼图相关的prompt和工具说明。凭据仅在进程内注入，不进入运行日志。

| 指令 | 旧流程 | 拼图流程 |
|---|---|---|
| 去那个像打印机的设备那里 | 122.29秒，第二次模型请求超时 | 67.86秒，4次模型请求，3次工具调用，insufficient_evidence |
| 去那个白色柜子那里 | 120.27秒，第一次模型请求超时 | 360.58秒，5次模型请求，4次工具调用，ambiguous |

“打印机”拼图流程连续改写三组检索，未找到明确目标；“白色柜子”先改写查询，再翻到第2、3页，最终要求在 indoor-041 与 S016 之间澄清。这些结果是模型判断，未作人工语义真值确认。拼图支持直接结束，但实际模型没有在首屏完成选择。

两条旧流程均超时，不能用它们计算正常完成任务的提速倍数。白色柜子的拼图任务，尚未看图的第一次模型请求已等待81.82秒；工具调用每次约0.6–0.8秒。计时是客户端模型请求等待时间，无法分离网关排队、网络和模型内部推理。

## 结论与下一步

本轮证实检索与看图可合并为一次工具返回，没有证实整体提速。当前主要问题包括模型请求等待波动，以及首屏候选不够相关导致改写查询、翻页和累积看图。后续应先定位网关延迟，并检查同指令的检索排序/查询表达，再决定拼图候选数量和是否改为主服务默认行为。没有自动扩大候选页或更换模型。
